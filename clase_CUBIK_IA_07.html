Sección 05

Deep Dive Técnico

Análisis en profundidad de cada tema técnico abordado en la sesión

01

Agente Multiagente COBOL — Prototipo BCI

▾

Armin demostró un prototipo ya entregado a BCI para generación automática de código COBOL batch. El proyecto nació de un requerimiento directo de la gerencia que solicitaba un "prototipo experimental que permita generar código COBOL batch desde cero utilizando lenguaje natural."

Arquitectura de 4 agentes:

  • Planificador: Recibe instrucción en lenguaje natural, selecciona la metodología de planificación (PRD, historias de usuario, o integral). Si la primera falla, replanifica con otra.
  • Codificador: Genera código COBOL usando Gemini como modelo base, con instrucciones personalizadas (cabeceras empresariales BCI, formato VSAM/Datacom, nomenclatura interna).
  • Validador: Compila el código y verifica el return code (0004 = exitoso). Si falla, devuelve al planificador para iteración.
  • Documentador: Genera documentación técnica del programa. Fue agregado como extra ("la cuchufleta" del gerente).

Ejemplo demostrado:

"Actúa como un experto COBOL mainframe. Genera un programa batch que realiza un pareo (match file) entre dos archivos: un archivo de personas/clientes y un archivo de tarjetas de crédito. Busca por RUT del cliente las tarjetas activas y luego consulta la base de datos de cuentas corrientes para traer el producto asociado."

Desafíos técnicos identificados:

  • BCI usa Datacom en vez de DB2 (estándar universal de COBOL), requiriendo entrenamiento específico del modelo.
  • La conexión al mainframe IBM vía Py3270 (librería Python que simula terminal TN3270) no se completó en la Fase 1.
  • La IA nunca genera exactamente el mismo programa dos veces — se necesita machine learning para consistencia.
  • Los copies de Datacom cambiaron recientemente, hay que actualizar la nomenclatura del RAG.

Próximos pasos propuestos:

Construir una aplicación web donde el banco pueda cargar estructuras de base de datos al RAG mediante formulario (interfaz tipo CRUD). El RAG almacenará toda la nomenclatura interna (tablas, copies, campos clave, archivos legacy) en una base vectorial en la nube. Armin estima "pega para 2 años" en este RAG.

02

APIs, API Keys y seguridad

▾

Armin dedicó tiempo a explicar conceptos fundamentales para que el equipo entienda la infraestructura detrás de las herramientas de IA:

API (Application Programming Interface):

"El mensajero que te conecta y trae la información." Cuando una aplicación necesita usar el cerebro de Gemini, la API es el canal de comunicación. El equipo participó: Luis Cornejo la definió como "herramienta de integración", José Martínez como "un puente entre plataformas".

API Key:

"La llave para llegar al cerebro." Comparable a una suscripción de Spotify (básica/media/premium). Las APIs gratuitas de Gemini Canvas son limitadas pero suficientes para prototipado. Las APIs de pago ofrecen acceso a modelos más potentes y mayor volumen.

Seguridad crítica:

  • Nunca compartir API Keys públicamente.
  • GitHub bloquea cuentas si detecta archivos .env con keys expuestas.
  • En desarrollo local se usa archivo .env (environment) que no se sube a repositorios.
  • En producción las keys van en variables de entorno del servidor.

Caso Suno:

Suno (generador de música IA) no vende su API, obligando a usar su plataforma. Armin comentó que tiene ideas para crear aplicaciones mejores que Suno pero necesita acceso al API que no está disponible.

03

Embeddings y bases de datos vectoriales

▾

Los embeddings son la transformación que hace la IA del texto humano a representaciones numéricas (vectores) que permiten búsquedas semánticas y comparaciones de significado.

Ejemplo didáctico del "perro":

Si el contexto anterior dice "el perro corrió al parque y...", la IA genera vectores para posibles continuaciones: "ladró" (85% probabilidad), "durmió" (10%), "voló" (0.1%). Selecciona la opción con mayor porcentaje según el contexto acumulado. Por eso cuando "le meten mucha ensalada de mensajes", se equivoca — los vectores se confunden.

Tipos de bases de datos mencionadas:

  • Relacionales: SQL Server, MySQL (las clásicas)
  • No relacionales: MongoDB (documentos JSON)
  • Transaccionales: Datacom de IBM (usada en BCI)
  • Vectoriales: Supabase (recomendada), Pinecone (escalable), MongoDB con vectores (emergente)

Recomendación de Armin:

"Empiecen desde ya a estudiar bases de datos vectoriales. Pueden hacer su NotebookLM de bases de datos vectoriales." Supabase es la empresa que más ha crecido en los últimos 2 años en este espacio.

04

Gemas vs NotebookLM vs Agentes

▾

Gemas (Gemini):

Asistentes personalizados con instrucciones y base de conocimiento adjunta (archivos). Son como un chat mejorado con contexto. No hacen embedding real — simplemente adjuntan archivos que el modelo lee en cada consulta. Ejemplo: Armin tiene una gema que genera notebooks para Databricks basándose en un archivo de ejemplo adjunto.

NotebookLM (Google):

Herramienta tipo RAG básico. Permite adjuntar fuentes desde Drive y genera resúmenes, infografías y audio. Tiene más funcionalidades que una Gema (busca en Drive, genera multimedia), pero sigue siendo "una gema más grande" — no hace embedding real como un agente. Armin lo usa para generar listas de asistencia desde transcripciones.

Agentes (LangChain/LangGraph):

Automatización completa con grafos neuronales, base vectorial real (Supabase/Pinecone), aprendizaje (machine learning), y orquestación autónoma. Pueden aprender de sí mismos, iterar, y eventualmente operar sin intervención humana (deep learning). La curva de aprendizaje es de 1.5-2 años.

Clave diferencial:

"Notebook tiene un universo de posibilidades más grande porque además de adjuntar archivos tiene fuentes de otros lados y automatiza generación de video. Pero sigue siendo un chat de Gemini — no piensa como un agente, no hace embedding real."

05

Prompt Engineering: comandos "no negociable"

▾

Ante la pregunta de Rodrigo (Arbersen) sobre cómo evitar que la IA genere código incorrecto o reutilizado, Armin explicó técnicas avanzadas de prompt engineering:

Comando "No negociable":

Un modificador en el prompt que establece restricciones absolutas. Ejemplo en música: "Agrégame un piano. La guitarra y el bajo NO son negociables" — la IA añade el piano sin eliminar los otros instrumentos. En código COBOL: "Respeta los márgenes COBOL. NO elimines ni modifiques la estructura de cabecera. NO es negociable."

Otras técnicas mencionadas:

  • Dar "personalidades" a los agentes con roles específicos (planificador, codificador, validador)
  • Usar marcadores de cambio ("aquí modifiqué") para rastrear modificaciones
  • Templates con instrucciones como "analiza el código original" y "respeta la estructura existente"
  • Control de temperatura para reducir variabilidad en las respuestas

Limitación honesta de Armin:

"Tampoco te lo garantiza. Nunca te va a generar un programa igual siempre. Para lograr consistencia hay que trabajar con machine learning para que aprenda de sí misma."

06

React, React Native y el camino a apps móviles

▾

Armin explicó por qué Gemini Canvas genera código en React en lugar de HTML puro:

Historia de React Native:

Un programador de Facebook creó React Native después de que Mark Zuckerberg reconociera públicamente que apostar por HTML5 fue un error ("la cagué"). HTML5 no manejaba bien los diferentes dispositivos móviles. React Native combina lo mejor de HTML5 y JavaScript con acceso a periféricos del dispositivo (cámara, sensores).

Ruta de progresión:

  • React: Web para ordenadores (lo que genera Gemini Canvas actualmente)
  • React Native: Apps multiplataforma (Android + iOS) — Facebook, Instagram lo usan
  • Android Studio + Flutter: Apps nativas con Google — importa código React, lo transforma automáticamente

Por qué importa:

"Cada aplicación que hacemos con Canvas está a un solo paso de pasar a React Native y después a Android Studio. El portal CUBI-K ya se ve como app en el teléfono." Esto significa que los prototipos que el equipo cree ahora con Gemini Canvas podrán evolucionar a apps móviles reales.

Requisitos de Android Studio:

Mínimo 32 GB RAM y procesador Core i12 de octava generación. "Es pesadísimo" pero maneja la conversión casi automáticamente.
